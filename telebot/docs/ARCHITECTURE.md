
# Архитектура

## Принципы

1. **Один процесс, одно соединение с БД.** Бот работает как один asyncio-процесс. `Database` держит единое соединение `aiosqlite` на всё время работы.

2. **Роли через `subscriber_level`.** Три уровня: `host`, `provodnik`, `passenger`. Админ — по `ADMIN_ID` в `.env`, не хранится в БД.

3. **Проверки прав в момент действия.** Не полагаемся на `data['user']` из middleware — каждый хендлер, где важны права, читает пользователя из БД через `get_user` или `_helpers`.

4. **FSM для пошаговых диалогов.** Создание игротеки, редактирование, добавление игры, ответ на опрос — через `StatesGroup`.

5. **Уведомления — отдельный модуль.** `notifications.py` содержит `_safe_send` с обработкой `TelegramForbiddenError` и `TelegramRetryAfter`. Все уведомления идут через него.

6. **Напоминания — APScheduler.** Задача `check_and_send_reminders` запускается каждые 10 минут, проверяет окна 23–25 часов и 50–70 минут до первой игры дня.

## Поток обновления (Update)
Telegram → aiogram Dispatcher → AccessMiddleware → Router
↓
handlers/start.py
handlers/schedule.py
handlers/my_games.py
handlers/host/*


**AccessMiddleware** пропускает:
- админа (`ADMIN_ID`) — всегда;
- одобренных (`is_approved=1`) — всегда;
- неодобренных — только `/start` (чтобы оставить заявку).

Остальные действия — отказ с сообщением.

## Роли и права

| Действие | passenger | provodnik | host | admin |
|---|---|---|---|---|
| Просмотр расписания | ✅ | ✅ | ✅ | ✅ |
| Запись на открытые игры | ✅ | ✅ | ✅ | ✅ |
| Запись на 🔒 игры | ❌ | ✅ | ✅ | ✅ |
| Создание игротеки | ❌ | ❌ | ✅ | ✅ |
| Добавление игры в чужую игротеку | ❌ | ❌ | ✅ | ✅ |
| Удаление своей игры в чужой игротеке | ❌ | ❌ | ✅ | ✅ |
| Удаление любой игры | ❌ | ❌ | только в своей | ✅ |
| Редактирование игротеки | ❌ | ❌ | только своей | ✅ |
| Создание опроса | ❌ | ❌ | только в своей | ✅ |
| Просмотр участников | ❌ | ❌ | только своих игр | все |

## Схема данных (кратко)

- `users` — пользователи и роли
- `games` — каталог игр
- `game_nights` — игротеки (дата, место, хост)
- `game_sessions` — игры в рамках игротеки (время, места, автор)
- `registrations` — записи игроков
- `notifications_log` — лог отправленных напоминаний
- `availability_polls` — опросы о времени
- `availability_responses` — ответы на опросы

Подробно — `docs/DATABASE.md`.

## Ключевые решения

- **`created_by_user_id` в `game_sessions`.** Позволяет хосту удалять свои игры в чужих игротеках.
- **Атомарная запись** через `BEGIN`/`COMMIT` в `register_for_session`.
- **`ON CONFLICT DO UPDATE`** в `upsert_availability_response` — повторный ответ перезаписывает предыдущий.
- **Fallback локали** в `create.py` — если `ru_RU` недоступна, календарь открывается на английском, бот не падает.
